## 三、简介（整段复制进 B 站简介框）

```
AI 给你写的代码，你检查过吗？

现在写代码的越来越快了，AI 一次给你吐出几百行，质量却不一定经得起看。
更麻烦的是：广告注入、推广外链、供应链投毒这些东西，
往往不是"代码写错了"，而是"代码里夹带了别的东西"——它照样能跑、照样过测试。

dsh-code-quarantine 是个开源的「代码检疫闸」：在代码被写进项目之前，先过一道检查。

▍它做什么

· 24 条规则，分四层
  ① 广告注入 5 条：推广话术 + 外链共现、未被消费的硬编码 URL、可疑域名、推广联系方式、外链脚本/iframe
  ② 供应链投毒 12 条：curl | bash、凭据外发、编码载荷、postinstall 钩子、仿冒包名、非官方源、TLS 降级…
  ③ 架构偏离 6 条：分层违规、模块级副作用、可疑命名、签名漂移、循环依赖、构造器 I/O（Python AST 判定）
  ④ AI 复核 1 条：规则看不出的语义问题，交给模型补漏

· 两种模式
  写入前：挂在 PreToolUse / 落盘前工具上，命中 CRITICAL 直接拦住这次写入
  落盘后：审计整个仓库，输出 BLOCK / REVIEW / SAFE 和退出码 0/1/2，可直接当 CI 卡点

· 四个入口
  · DeepSeek-Harness：输入框右侧一个图标按钮，点开是六标签卡片，跟本地面板同构
  · Claude Code / WorkBuddy：输入框里打 /dsh-code-quarantine
  · 本地控制面板：独立小窗，荷鲁斯之眼图标，可钉任务栏
  · 状态栏：对话底部常驻一行 "👁 BLOCK · 8C/16W · 13 文件 · 2m 前"

· 看到问题之后能动手
  跳转（编辑器打开 file:line）· 编辑（上下文弹窗，改前自动备份，改完只重扫该文件）
  交给 AI（生成含规则/位置/证据/修复方向的指令，一键复制）· 豁免（写进豁免清单）
  每次改动都记进 append-only 的修复历史，标出 current / reverted / stale / gone

· AI 复核是可选的
  没有密钥就整层跳过，报告会写"未启用"，不会假装复核过。
  模型不能推翻 CRITICAL；项目配置里写的端点不会自动启用（防止克隆一个仓库就把源码发出去）；
  被审查的代码按不可信数据处理，防提示注入。

▍它有多准

· 8 个真实开源库（starlette / pydantic / fastapi / rich / sqlalchemy / click / httpx / anyio）
  581 个 .py 文件 → 0 个 CRITICAL 误报
· CPython 3.13 标准库 Lib/ 537 个 .py → 0 CRITICAL
· npm 源码 npm/lib 110 个 .js → SAFE
· 13 个恶意样本全部命中，干净项目 0 条发现
· 188 个单元用例（含 26 个安全用例）+ 100 个地狱式功能用例 + 44 项端到端 + 133 项插件断言

▍它的边界（说在前面）

· 只有 Python 有真正的 AST 判定，其他语言明确降级为词法层，并在报告里声明这个缺口
· 加密、运行时拼接的载荷静态不可还原，得靠运行期行为侧兜底
· 它不替代 SAST 和依赖审计，只守"输出被写进项目"这一道门
· 零第三方依赖，纯 Python 标准库，MIT 协议

源码：https://github.com/kleinklein0824/dsh-code-quarantine

视频里的域名全是假的样例，与任何真实服务无关。
```
